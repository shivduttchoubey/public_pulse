Auditable vs Non-Auditable Security Assertions

Auditable Items

Auditable Item Status Reason
Encryption at rest Yes Binary state — encryption enabled or disabled can be proven without exposing keys.
Encryption in transit / TLS version Yes TLS handshake and protocol version are externally verifiable assertions.
Database public exposure Yes Network reachability can be verified without revealing internal addresses.
MFA enforcement Yes Authentication policy exists as a provable configuration state.
Session timeout policy Yes Timeout threshold is a numeric configuration value.
Backup recency Yes Backup timestamps can prove backups occurred within required periods.
SSL certificate validity / expiry Yes Certificate metadata is already public and easily verifiable.
Brute force / lockout policy Yes Lockout thresholds are policy-level assertions.
Firewall and IDS active status Yes Running/not-running is a binary system state.
GDPR deletion policy implementation Yes Deletion workflows and audit trails can be proven without revealing user identities.
Access review recency Yes Timestamps prove reviews occurred within required intervals.
VPN requirement for admin access Yes VPN enforcement exists as a network policy configuration.
Compliance badge validity (ISO, HIPAA) Yes Underlying technical controls can be validated.
Software patch level Yes Versions and CVE patch status are objective facts.
Password complexity policy Yes Password rules are provable without exposing actual passwords.
Data minimisation — fields collected Yes Schema structure can be audited without exposing records.
Log retention period Yes Retention settings are policy-level configurations.
Open port surface Partial Unexpected open ports can be detected, but full exposure details are sensitive.
Number of privileged accounts Partial Ranges or thresholds can be proven without exposing identities.

Non-Auditable Items

Non-Auditable Item Status Reason
Specific user's data contents No Proving actual record contents requires revealing the data itself.
Whether a specific individual was breached No Checking named records breaks privacy and anonymity guarantees.
Internal network topology / IP ranges No Revealing infrastructure mapping creates security risks.
Vendor/third-party sub-processor security No External providers fall outside the proof boundary.
Human behaviour and intent No Intent and misuse require interpretation, not binary verification.
Future security posture No Proofs validate current state only and cannot predict future changes.
Algorithmic fairness / AI model bias No Bias analysis requires statistical evaluation rather than config verification.
Physical data centre security No Physical security requires human inspection and real-world controls.
General Rule:
Anything reducible to a binary or numeric assertion about a system's current configuration or state can generally be audited using cryptographic proofs or zero-knowledge approaches. Anything requiring disclosure of actual content, human interpretation, external dependencies, or future prediction cannot be directly audited in this framework.
